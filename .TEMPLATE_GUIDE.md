# Python Pipeline Template Reference Guide

This document defines the exact structure of `python_template`, explaining what each file and directory does, how Git tracks it, and how Copier handles it during project generation (`copier copy`) and updates (`copier update`).

---

## Repository Layout

```text
.
├── .TEMPLATE_GUIDE.md          # Template documentation (excluded from generated projects)
├── .agents/                    # AI coding agent context, plans, prompts & skills
│   ├── plans/
│   │   └── .gitkeep
│   ├── prompts/
│   │   └── .gitkeep
│   └── skills/
│       └── python-patterns/
│           └── SKILL.md
├── .credentials/               # File-based secrets (e.g., JSON keys, .pem) — contents ignored
│   └── .gitkeep
├── .env.example                # Template for environment variables & credential file paths
├── .gitignore                  # Ignores .venv, .env, .credentials/*, assets/*, output/*
├── README.md.jinja             # Rendered into README.md in generated projects
├── app/                        # Modular Python pipeline logic (parser, assets, renderer, etc.)
│   └── __init__.py
├── assets/                     # Cached remote media & intermediate files — contents ignored
│   └── .gitkeep
├── build.py                    # Thin CLI entrypoint orchestrating the pipeline
├── copier.yml                  # Copier prompts, exclusions & post-generation tasks (excluded)
├── data/                       # Small static inputs tracked in Git
│   └── .gitkeep
├── output/                     # Compiled artifacts (PDFs, PNGs, exports) — contents ignored
│   └── .gitkeep
├── pyproject.toml.jinja        # Rendered into pyproject.toml with uv & tool configuration
├── skills-lock.json            # Lockfile tracking installed AI agent skills
└── templates/                  # HTML, CSS, or Jinja formatting templates
    └── .gitkeep
```

## 1. Template Control & Documentation Files

### `copier.yml`
* **Purpose:** Defines interactive prompts (`project_name`, `package_name`, `description`, `python_version`), excluded files (`_exclude`), and automated setup commands (`_tasks`: pinning Python, running `uv sync`, and initializing `git`).
* **Git (Template):** **Tracked.** Always commit changes to `copier.yml` before running `copier copy` or `copier update`, as Copier reads from your template's committed Git state.
* **Copier:** **Excluded.** Listed under `_exclude` so it is never copied into generated projects.

### `.TEMPLATE_GUIDE.md` *(This File)*
* **Purpose:** Reference documentation explaining how to maintain and extend `python_template`.
* **Git (Template):** **Tracked.**
* **Copier:** **Excluded.** Listed under `_exclude` in `copier.yml` so new projects stay clean.

### `.copier-answers.yml` *(Auto-generated in New Projects)*
* **Purpose:** Created automatically by Copier inside every generated project to record the source template commit hash and your prompt answers.
* **Git (New Project):** **Tracked.** Keep this file committed in generated projects so `copier update` can merge future template improvements cleanly.

---

## 2. Configuration, Environment & Secrets

### `pyproject.toml.jinja`
* **Purpose:** Defines project metadata, target Python version, baseline dependencies (`python-dotenv`), and dev tool rules (`ruff`, `pytest`).
* **Git (Template):** **Tracked** with the `.jinja` suffix.
* **Copier:** **Rendered.** Copier replaces Jinja variables (`{{ project_name }}`, etc.) and outputs `pyproject.toml`.

### `.gitignore`
* **Purpose:** Blocks virtual environments (`.venv/`), secrets (`.env`, `.credentials/*`), cached media (`assets/*`), and generated outputs (`output/*`) from entering Git history, while explicitly allowing `!.gitkeep` placeholders.
* **Git & Copier:** **Tracked and Static Copy.**

### `.env.example`
* **Purpose:** Documents required environment variables and file paths to credentials (e.g., `GOOGLE_APPLICATION_CREDENTIALS=.credentials/service-account.json`) without exposing secrets.
* **Git & Copier:** **Tracked and Static Copy.** Copy to `.env` (gitignored) when working locally.

### `.credentials/`
* **Purpose:** Stores file-based secrets (e.g., Google service account JSONs, OAuth tokens, `.pem`/`.key` certificates) that cannot be stored as single-line strings in `.env`.
* **Git & Copier:** **Folder tracked via `.credentials/.gitkeep`; contents ignored and excluded.**

---

## 3. Code & Presentation Structure

### `build.py`
* **Purpose:** Thin top-level CLI entrypoint (`uv run build.py`) that loads `.env`, sets up logging and standard `pathlib` directory constants, parses CLI flags, and orchestrates pipeline steps. Keep core business logic out of this file.
* **Git & Copier:** **Tracked and Static Copy.**

### `app/`
* **Purpose:** Modular Python package housing core pipeline logic separated by concern (e.g., `parser.py` for ingestion, `assets.py` for downloading/caching, `renderer.py` for compilation).
* **Git & Copier:** **Tracked via `app/__init__.py` and Static Copy.**

### `templates/`
* **Purpose:** Stores presentation and formatting templates used by the pipeline (e.g., HTML/CSS files for PDF rendering, Jinja text templates).
* **Git & Copier:** **Tracked via `templates/.gitkeep` and Static Copy.**

### `README.md.jinja`
* **Purpose:** Starter project documentation pre-populated with the project name, description, and `uv run` quickstart commands.
* **Git (Template):** **Tracked** as `README.md.jinja`.
* **Copier:** **Rendered** as `README.md`.

---

## 4. AI Agent Context & Skills

### `.agents/` (`plans/`, `prompts/`, `skills/`)
* **Purpose:** Centralizes AI coding agent workspace files:
  * `plans/`: Implementation plans and architectural notes.
  * `prompts/`: Project specifications and prompt markdown files.
  * `skills/`: Reusable agent skill definitions (e.g., `python-patterns/SKILL.md`).
* **Git & Copier:** **Tracked and Static Copy.** Updates made to `.agents/skills/` in `python_template` can be synced into existing projects via `copier update`.

### `skills-lock.json`
* **Purpose:** Tracks versions and sources of installed AI agent skills so skill setups stay reproducible across projects.
* **Git & Copier:** **Tracked and Static Copy.**

---

## 5. Data, Cache & Artifact Directories

### `data/`
* **Purpose:** Small, static input files required by the pipeline (e.g., sample CSVs, lookup JSONs, source Markdown).
* **Git & Copier:** **Tracked via `data/.gitkeep`.** Small text inputs are tracked in Git; add large raw datasets to `.gitignore`.

### `assets/`
* **Purpose:** Local cache for downloaded remote media (e.g., images fetched from URLs or APIs) so scripts run offline without repeated network requests.
* **Git & Copier:** **Folder tracked via `assets/.gitkeep`; contents gitignored and excluded.**

### `output/`
* **Purpose:** Destination directory for compiled artifacts (e.g., PDFs, PNG previews, transformed exports).
* **Git & Copier:** **Folder tracked via `output/.gitkeep`; contents gitignored and excluded.**

---

## Maintenance Rules for `python_template`

1. **Always commit before copying:** Copier pulls from committed Git history—uncommitted changes in `python_template` will not appear in `copier copy` or `copier update`.
2. **Preserve empty directories:** Git ignores empty folders; always include a `.gitkeep` file (or `__init__.py` in `app/`) when adding new directories.
3. **Keep template-local `.venv` out of Git:** A local `.venv/` inside `python_template` (for editor/type-checker support) is safe as long as `.venv` stays in `.gitignore` and `copier.yml` `_exclude`.
